## 3. الخلل الحقيقي الذي كشفه هذا الاختبار

### 3.1 Symptom

```
UnhandledPromiseRejectionWarning: ReferenceError: esc is not defined
    at Object.batchHTML (D:\Malahy\assets\report\payroll-report.js:379:17)
```

### 3.2 السبب

`batchHTML()` تستدعي `esc(...)` في سطر ملاحظة الدفعة، **دون أن تُعرِّف `esc`**:

```js
h += totalsBlock(m);
if (m.note) h += '<div class="foot">' + esc(ellipsis(m.note, charWidth(paper) + 14)) + '</div>';
//                                                        ^^^ غير معرَّف هنا
```

كل الدوال الأخرى في الملف تصرّح `var t = util(), esc = t.esc`. هذه وحدها نسيتها.

### 3.3 الخطورة — لماذا كانت نائمة

فحصت كل مواضع الاستدعاء: **لا يمرّر أي مسار في الواجهة `note` إلى `payCommit`**
(`index.html:5194` يقرأ `opts.note||''`، والمواضع الثلاثة للاستدعاء لا تمرّره).
فالسطر لم يُنفَّذ قط. **لغم نائم**: أول من يمرّر ملاحظة على دفعة يُسقط التقرير.

### 3.4 الإصلاح

`assets/report/payroll-report.js:371` — تصريح `esc` داخل `batchHTML`، مطابقًا لبقية
الدوال. **إصلاح نطاق متغيّر في المُصيِّر، لا علاقة له بقواعد الحساب المالي.**

### 3.5 الفحص الشامل للمشتقات

```js
MISSING DECL in wrapHTML  (uses esc 1x)   -> إنذار كاذب: يستخدم util().esc صحيحًا
MISSING DECL in batchHTML (uses esc 1x)   -> الخلل الحقيقي، مُصلَح
```

### 7.3 عطل تشغيلي اكتُشف أثناء الطريق (غير متعلق بالبرنامج)

نافذة الطباعة أنشأتها أولًا بـ `show:false`، ثم أضفت نافذة استطلاع طابعة قبلها.
**تحميل `data:` URL فشل بـ `ERR_FAILED (-2)`** فأُلغيت المهمة مرتين بحارس الأمان.

تشخيص بعزل المتغيّرات أثبت أن إعداد الإنتاج `main.js:370-378`
(`show:false` + `javascript:false` + `data:` URL) **يعمل**، وأن المشكلة كانت
النافذة الاستطلاع المُدمَّرة قبله، لا إعداد النافذة. أُعيدت الكتابة بنافذة واحدة
كما في `main.js` فنجحت.

**دلالة إضافية:** `webContents.print` لا يُبلّغ عن فشل تحميل الصفحة إلا عبر
`did-fail-load`؛ ومع `await loadURL` غير المحمي يبقى الخطأ بلا معالجة. أما `main.js`
يستدعي `await win.loadURL(...)` داخل `try` فالتعامل موجود عنده.
