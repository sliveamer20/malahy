## 3. العيب G-2 — أمان الترحيل تحت الانقطاع

### السلوك السابق والخطر

كان `legacyHandled = true` يُكتب **قبل** معالجة الأسبوع:

```js
if (w.legacyHandled) return;
w.legacyHandled = true; changed = true;   // الختم قبل العمل
```

**الخطر:** لو انقطع التنفيذ (استثناء في `migrateEmployee` على موظف تالٍ) وبقيت `_emp.list` في الذاكرة بحالة جزئية، فأي حفظ لاحق غير متعلق (مثل تسجيل حضور) **يُersist** تلك الحالة ⇒ الأسبوع مختوم بلا استيراد ⇒ **فقد أيام دائم**.

**ومنحازه أشدّ:** `e.legacySchema = SCHEMA` كان يُكتب دائمًا حتى لو لم يُستورد شيء — فيُعلن «انتهى الترحيل» كذبًا.

### التغييرات

| # | الموقع | التغيير |
|---|---|---|
| G-2.a | `migrateEmployee()` | `legacyHandled` يُكتب **بعد** اكتمال معالجة الأسبوع (نهاية `forEach`) وفي مسارات الإ.final (غير مقروء / مدفوع / بلا أجر) |
| G-2.b | `migrateEmployee()` | ختم المخطط **مشروط**: `var allHandled = ...every(w => w.legacyHandled)`؛ ولا يُكتب `legacySchema`/`legacyMigratedAt` إلا إذا عولج كل أسبوع |
| G-2.c | القيمة المُرجعة | حقل جديد `pending: !allHandled` |
| G-2.d | الحارس الفعّال | حارس `dayRec(e,key)` + حارس `legacyId` — وهما حارسان **لا يعتمدان على العلامات**، فيمنعان التكرار حتى بعد استعادة نسخة أقدم |

**لماذا هذا آمن الآن:** العلامة لم تعد تُعلن النجاح. لو انقطع التنفيذ، يبقى ذلك الأسبوع بلا ختم ⇒ يُعاد في التشغيل التالي ⇒ وحارس `dayKey` يمنع ازدواج ما استُورد فعلًا.

## 4. المرحلة C — التراجع المحمي

### الدالة الجديدة `rollbackMigration(e, opts)`

**نطاق الحذف = الوسوم فقط:**
- الأيام التي `src === 'legacy'`
- العمليات التي تحمل `legacyId` أو بادئة `lg_`
- علامات الأسابيع: `legacyHandled` / `legacySettled` / `legacyMigrated`
- `legacySchema` / `legacyImport` / `legacyMigratedAt`

**لا يمسّ أبدًا:** `weeks` (مصدر الحقيقة)، `payouts`، الأيام غير المُرحَّلة، العمليات المُسجَّلة مباشرة.

**الحارس القاطع — يُرفض عند:**
1. **أي دفعة** بـ `ts >= legacyMigratedAt`
2. **أي عملية مُسدَّدة** (`settledBy`)

**سبب الرفض:** فكّ الترحيل بعد تحرّك أموال يربط دفعاتٍ محقّة بأيام محذوفة ويُفسد الثنائية `outstanding = net − paid`.
